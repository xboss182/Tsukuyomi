# 导入与恢复说明

Tsukuyomi 的小说导入/抓取运行在桌面版（Electron）主进程队列中：任务在应用内排队、串行执行，**不依赖操作系统计划任务、独立服务或外部队列**。

## 抓取任务队列

- 从来源导入作品时，任务进入本地队列（IndexedDB `import-jobs`），由主进程串行执行。
- 每个来源有请求间隔（per-host cooldown）；调用第三方抓取服务商受**费用预算**控制（按月额度、单次成本、每日上限）。
- 任务状态：`queued`（排队）→ `discovering`（发现目录）→ `fetching`（抓取章节）→ `applying`（写入书库）→ 终态 `completed` / `completed_with_errors` / `failed` / `cancelled`。

## 重启恢复

- 应用启动时会自动把上次中断的任务（`discovering` / `fetching` / `applying`）重新排队并继续执行，控制台会记录恢复数量。
- 正常退出时也会把未完成任务标记为中断，保证下次启动继续。
- 恢复只针对任务状态，不涉及任何凭据或远程内容备份。

## 健康与诊断

- 桌面版提供本地诊断接口（`import-diagnostics`），只读返回任务队列状态：`ready`（无排队/执行中的任务）、排队数、执行中数、已恢复数以及每个任务的进度与失败章节数。
- **应用就绪** 与 **单个任务失败** 是两回事：任务失败只影响该任务，不影响应用可用性。

## 手动备份与恢复

- 「设置 → 导入资料/导出资料」会把书库、章节内容、导入任务与抓取任务状态打包成单个 JSON 文件导出。
- 导出的文件**不包含**任何服务商凭据。
- 恢复时文件会先整体校验再替换书库，损坏的备份不会清空现有数据。

## 抓取服务商凭据

- 第三方抓取服务商（Scrape.do / ScrapingAnt / ZenRows / Zyte）的密钥保存在系统安全存储（Electron `safeStorage`），不写入代码、日志或导出文件。

## 故障排查

- 单个任务失败：查看任务的 `status` 与 `error`（错误码、是否可重试），可对失败章节重试。
- 应用启动后任务没有继续：确认桌面版运行中；`import-diagnostics` 会显示队列状态。
- 队列被清空/损坏：从「导入资料」恢复最近的导出文件。
